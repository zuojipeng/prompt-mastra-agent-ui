## 执行步骤

1. 协调人确认五名评审的资格和利益冲突声明。
2. 每名评审只接收自己的评审包和一份 `templates/pitch-ballot.md` 副本。
3. 五人独立评分，锁定前禁止讨论；协调人不得展示其他人的分数。
4. 收齐五份有效表后才聚合。平票按模板规则处理，不临时修改权重。
5. 聚合结论锁定后再公布胜选编号，并为该提案建立节拍表任务。

## 禁止事项

- 不把 `pitches.md` 底部的生产说明、Agent 或模型路由交给评审。
- 不在收齐五份表前宣布领先提案。
- 不以 Showrunner 或 Agent 的偏好替代真人门禁。
- 不在评审包中加入 A/B/C 分组、作者、模型、成本或生成路径。

评审包由 `npm run build:creative-review-packets` 从九案源文件生成。重新生成会保持每个席位的固定顺序；提案内容发生变化时必须升级包版本并重新评审。

`npm run validate:creative-pitch-gate` 只有在五份合格、独立、锁定的 JSON 票据到齐且与 `manifest.json` 匹配后才会通过。当前返回 `HUMAN_GATE_PENDING` 是正确状态，不代表系统故障。
